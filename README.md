Test Report 자동 생성기
광케이블 출하 시험 데이터(엑셀/CSV)를 불러오면 **규격 판정, 표지(Cover), Test Report(TYPE)**를 사내 양식 그대로 한 번에 만들어 주는 웹 도구입니다.
핵심: 시험 데이터는 사용자 PC 밖으로 한 바이트도 나가지 않습니다. 웹페이지로 배포되지만 서버가 없고, 모든 처리는 브라우저 안에서만 이루어집니다.
왜 만들었나
기존 방식	이 도구
시험 데이터를 양식에 손으로 옮겨 적음	파일을 불러오면 양식에 자동으로 채워짐
규격 합부를 눈으로 대조	항목별 자동 판정, 불합격 칸 빨간색 표시
표지와 본문에 같은 정보를 두 번 입력	한 번 입력하면 표지, 본문에 동시 반영
수량, 배치번호를 직접 계산	드럼 수, 총 길이, 배치 목록 자동 계산
사내 보안 때문에 웹 도구 사용 불가	데이터 전송이 없는 구조라 보안 정책과 충돌 없음
보안 설계
품질 데이터는 외부 반출이 금지된 사내 자료입니다. 그래서 "업로드하지 않는 웹 도구"로 설계했습니다.
브라우저 내부 처리: 파일은 브라우저 메모리에서만 읽고, 결과 엑셀도 브라우저에서 생성해 바로 저장합니다. 서버가 존재하지 않습니다.
통신 원천 차단: `index.html`의 보안 정책(Content-Security-Policy)에 `connect-src 'none'`을 지정해, 코드에 실수가 있어도 브라우저가 외부 통신 자체를 거부합니다.
오프라인 실행: GitHub Actions가 엑셀 라이브러리(ExcelJS)까지 포함한 오프라인 패키지를 만들어 줍니다. 받아서 `index.html`을 더블클릭하면 인터넷 없이 사내 PC에서 그대로 동작합니다.
실제 데이터 업로드 방지: `.gitignore`가 엑셀/CSV/PDF 파일을 차단하고, GitHub Actions가 샘플 폴더 밖의 데이터 파일을 발견하면 배포를 중단합니다.
자동 보안 점검: 테스트 코드가 핵심 파일에 통신 코드(fetch, XMLHttpRequest 등)가 들어가 있지 않은지 매번 검사합니다.
공개 저장소에는 가짜 데이터만: 샘플 데이터와 규격값은 모두 시연용 예시값입니다. 고객사명도 일반 명칭(Customer Order No.)으로 바꿔 두었습니다.
사용 방법
페이지를 엽니다 (GitHub Pages 주소, 또는 사내 PC에서 `index.html` 더블클릭)
시험 데이터 불러오기: 원본 엑셀에서 제목 행부터 데이터 끝까지 복사해 붙여넣기 칸에 Ctrl+V. 열 연결 확인에서 자동 연결 결과 점검
표지 정보 입력: Cable Type을 고르면 색상과 규격이 자동 적용됩니다. 수량, 배치번호, 제품명은 자동 계산되며 필요하면 직접 수정합니다
판정 확인 후 출력: PASS/FAIL과 불합격 항목을 확인하고 "엑셀로 저장" 또는 "PDF로 인쇄"
샘플로 먼저 해보려면 "샘플 데이터로 해보기"를 누르세요. 12건 중 1건(F09, 1550nm 손실)이 일부러 불합격으로 들어 있습니다.
데이터 입력 방식
엑셀에서 복사해서 붙여넣기 (권장): 파일 선택이 막힌 보안 환경에서도 사용 가능
파일로 불러오기 (.xlsx, .csv)
원본 양식 자동 인식
현장 원본 엑셀은 양식마다 열 제목이 다르고 구조가 복잡합니다. 이 도구는 다음을 자동으로 처리합니다.
2~4줄짜리 제목 행, 줄바꿈이 들어간 제목 칸, 가로/세로 병합 셀
첫 행에만 값이 있는 병합 셀(예: ORDER NO.)은 아래 행에 자동으로 채움
외경처럼 측정값이 2칸인 항목은 큰 값을 Max, 작은 값을 Min으로 정리
천 단위 쉼표(2,011), 보고서에 필요 없는 열(검사원, 전수검사 표시 등)은 무시
열 제목 없이 데이터만 붙여넣으면 입력 양식 순서로 인식
자동 연결 결과는 열 연결 확인 화면에 첫 행 값과 함께 표시됩니다. 틀린 항목만 고르면 같은 양식은 다음부터 자동으로 적용됩니다(이 PC 브라우저에만 저장).
규격 값 수정
화면의 규격 값 수정에서 제품군별 규격과 보고서 주문번호 열 제목을 바꿀 수 있습니다. 입력값은 사용하는 PC 브라우저에만 저장되므로, 실제 사내 규격이 GitHub에 올라가지 않습니다.
출력물
사내 Test Report 양식과 같은 배치의 엑셀 파일을 만듭니다.
Cover 시트: 표지 테두리, TEST REPORT 제목, Date / Order No. / PO No. / Customer / Cable Type / COLOR / Quantity / Batch No. 표, 작성·검토·승인 칸, 오른쪽 제품명 참고표
TYPE 시트: 상단 굵은 선, Test Report 제목, Product Name / Color / Inspection Date / Quantity(D/M) / QA RESULTS, 노란색 2단 머리글 시험 결과표 (머리글 행은 인쇄 시 매 페이지 반복)
불합격 값만 빨간 칸으로 표시
파일명 규칙: `YYMMDD MDU Drop Cable Test Report(2.9Riser)(TYPE-1).xlsx`
자동 입력 규칙
항목	자동 입력 방식	예
표지 Order No.	수주번호 앞 3마디	2026-S99-0001
표지 PO No.	원본 ORDER NO.	900001
Quantity	드럼 수 + 총 길이(Quantity(m) 합계, 없으면 OTDR 합계)	60 D/M (120km)
Batch No.	첫 번째 ~ 마지막 Drum No.	#01001 ~ #01060
FIBER NO.	원본에 없으면 1	1
Inspection Date	날짜를 MM/DD/YY로	07/13/26
모든 자동값은 화면에서 직접 고칠 수 있습니다.
공유 방법
용도	방법
사내 실무 사용 (권장)	Actions의 `test-report-single`을 받아 `test-report-generator.html` 파일 1개를 사내 공유폴더나 문서관리시스템(ECM)에 올리고 경로를 안내
시연, 외부 소개	GitHub Pages 주소 공유 (샘플 데이터로만 시연)
파일 1개짜리 도구는 모든 스크립트가 HTML 안에 들어 있어서, 문서관리시스템처럼 HTML 파일만 따로 열리는 환경에서도 동작합니다. 외부 통신 차단 설정은 그대로 유지됩니다.
규격 변경
`config/specs.js` 한 파일만 수정하면 화면, 엑셀, 자동 테스트에 모두 반영됩니다. 제품 종류(Type 1~8)와 제품별 규격(외경, 타이트버퍼, 1310/1550 손실)을 정의합니다.
> 실제 사내 규격값은 공개 저장소에 올리지 말고, 사내 PC에 받은 사본에서만 수정하세요.
자동화 (GitHub Actions)
`main` 브랜치에 코드가 올라오면 자동으로:
판정 로직 테스트 11종 실행 (원본 양식 구조 인식, 병합 셀, 경계값, 빈 값, 인쇄간격, 통신 코드 유무 등)
실제 데이터 파일 포함 여부 점검
엑셀 라이브러리를 내려받아 웹페이지 조립
모두 통과하면 GitHub Pages에 자동 배포 + 사내 PC용 오프라인 패키지 생성
테스트가 하나라도 실패하면 배포되지 않으므로, 판정 로직이 잘못된 버전이 사용자에게 전달되지 않습니다.
설치 (파일 업로드 없이 만들기)
파일 업로드가 막힌 환경을 위해, 모든 파일을 GitHub 웹 편집기에 텍스트로 붙여넣어 만들 수 있게 구성했습니다. 용량이 큰 엑셀 라이브러리는 저장소에 넣지 않고 GitHub Actions가 배포할 때 직접 내려받습니다.
새 저장소 생성 (Public, README 추가 안 함)
Settings > Pages > Source를 GitHub Actions로 변경
Add file > Create new file로 파일을 하나씩 생성 (경로 입력 + 내용 붙여넣기 + Commit)
마지막에 `.github/workflows/test-and-deploy.yml` 생성 → 자동 테스트, 배포 시작
Actions 탭에서 완료 확인 후 `https://<아이디>.github.io/<저장소명>/` 접속
사내 PC용 오프라인 패키지: Actions 실행 기록 하단 Artifacts의 `test-report-offline`을 내려받아 압축을 풀고 `index.html` 실행
로컬 테스트: `npm test` (Node.js 18 이상)
